# End-to-end review, 2026-10-24

One manual run of the demo path on `main` (plus PR #45 and a Backboard fix not yet merged), driven through Chrome: upload an image in `/studio`, generate with the live API, inspect the result. This records what works, what does not, and the issues filed. It supersedes nothing: `docs/implementation.md` and `docs/project.md` remain the spec, `docs/context.md` the board.

**Goal under test:** upload an image, confirm every part is a real product, assemble all of the parts.

## Setup used
- API: `RIVET_MODE=live`, real `rivet_engine`, port 8000, with the shared `.env` exported (`set -a; source .env; set +a`). The API does not read `.env` itself.
- Web: `pnpm dev` in `apps/web` with `apps/web/.env.local` (`NEXT_PUBLIC_RIVET_API_URL=http://localhost:8000`, `NEXT_PUBLIC_RIVET_USE_FIXTURES=false`). Next.js ignores the root `.env`.
- Personal keys go in a gitignored root `.env.local` (sourced after `.env`), never in the shared encrypted `.env`.
- Live vision with OpenAI needs `pip install -e '.[live]'`, `RIVET_VISION_PROVIDER=openai`, `RIVET_VISION_MODEL=gpt-4o`, `OPENAI_API_KEY`.
- Test images were drawn with Pillow; they are not committed.

## What works
| Step | Result |
|---|---|
| Image upload | `POST /api/assets/images` returns an asset id; preview shown |
| Job tracking | Progress, stages and errors reach the UI; failures show a typed code |
| Live vision (OpenAI) | "Interpreted as a rover (high confidence, live vision)" for a top-down 2WD chassis |
| Safety guard | Images read as `robot_arm` or `rc_car` are refused with `UNSUPPORTED_PROJECT_FAMILY` |
| Engine | 17 components, 11 assembly steps, 20 wires, 15 BOM lines, status `needs_review` (40 PASS, 4 WARN, 0 FAIL, 10 UNKNOWN) |
| Real parts | Adafruit and SparkFun SKUs, https links, prices; BOM total $110.80, `complete` |
| Honest findings | 2 blocking UNKNOWN: TT motor fit in the Shadow Chassis is not documented (SparkFun source linked) |
| Banner | "Live generation" with no synthetic label; "Fallback output" when the vision provider is the mock |
| Exports | BOM CSV (HTTP 200, `X-Rivet-Generation-Mode: live`), firmware ZIP (HTTP 200, compile `not_checked`) |

## What does not work
1. **3D scene is off-screen on real plans** (#70). The canvas grows to 1,600 to 12,000 px because the center column stretches to the tallest side panel. Root cause measured in the DOM.
2. **Backboard vision provider** (#61, #62). The image was uploaded as `image` with no extension (400 `File type '' is not supported`). A failed run returns HTTP 200 with `status: FAILED`, which was read as model output. After fixing both, the account still has no LLM credit. Backboard documents `files` as RAG attachments, so it is unproven that the model sees the image. The OpenAI provider worked.
3. **The image does not change the design** (#67). Mock intent and live vision both produced the same 17-part plan.
4. **Rejected images are a dead end** (#66). The user sees only an error string, not what the model understood.
5. **Real-product verification is manual** (#68). Link dates are set at curation time and never rechecked; the ESP32 board was out of stock when curated.
6. **No single view of the whole build** (#69). BOM (15), parts (17), findings (54) and steps (11) are separate; kit items with `visible=false` have no 3D representation.
7. **Estelle panel blames connectivity** (#65) when the API reports it is simply disabled.
8. **Local setup is manual** (#63): env loading, web env file, optional dependency, key handling.
